/goal

Implement the next Phase 12 vertical slice: Stage 3 prospective Fabric staging, one atomic native publication per completeRoot, and destruction from final committed reachability across Node/OpenGL and Wasm/WebGPU.

Primary outcome:
Ordinary React/Fabric rendering builds prospective host descriptions without changing live native state or committed JavaScript identity mappings. Each completeRoot publication submits exactly one structural transaction through the shared native application path. Native readers and rendering observe a coherent committed tree, and removal is decided from the final published relationships so a same-native-ID move inside one publication preserves its widget state and resources.

Resolve XF-LIFE-004/005/008/009 on the new ordinary publication path while retaining all six passing Stage 1 invariants and the applicable Stage 2 correctness guarantees. Replace the Stage 2 structural contract with the final-tree publication contract described below. A native publication acknowledgment establishes applied state and cleanup, not a presented-frame guarantee. Invalidation-driven scheduling and general frame/revision correlation remain Stage 4.

Alpha compatibility policy:
XFrames has been alpha from the outset and has made no stability commitment. Backward compatibility is not a default acceptance requirement: any retained compatibility must serve an identified consumer or migration need that justifies its implementation and maintenance cost. The existence of an earlier alpha API alone is not such a justification. Make the structural bridge breaking change deliberately: replace schema v1 and the immediate per-operation structural APIs with one final-tree publication model. Do not maintain a second mutation/destruction model, compatibility adapters or a deprecation period solely to preserve old alpha behavior. Preserve public React component and imperative widget APIs and initialization/ready callbacks as scope choices for this slice, without implying a general stability promise. Preserve the correctness guarantees needed by the new publication path. Migrate repository callers, fixtures, types and documentation to the new contract; document removed entry points and reject unsupported wire versions explicitly. Historical Stage 2 evidence is a regression baseline, not a requirement to keep its API or defective semantics.

Starting evidence (historical baseline, not compatibility requirements):
- Commit 476e2b3 delivered Stage 2 after Stage 1 commit 62f46a4. At that revision, both bindings exposed shared schema-v1 applyCommit and getCommitState APIs; compatibility exports delegated to one-operation transactions.
- Schema v1 supported surface 0, positive signed-32-bit native IDs, opaque correlation IDs and native uint64 sequence/revision counters serialized as decimal strings. Rejection did not mutate live state. Successful empty/no-op transactions advanced both counters once; failed application could consume a sequence without advancing the successful revision.
- Stage 2 used ordered immediate destruction, rejected explicit moves that violated intermediate ownership, and permitted intermediate visibility between successful operations. Its per-operation setChildren export returned its destroyed-ID JSON array synchronously after tree locks were released.
- All 343 native tests passed on Windows and Linux; 15 Fabric scenarios passed in each isolated development/production process. Real Node/Wasm parity matched 53 transaction results and populated/final native state.
- Both real runtimes passed 1,000 cycles in one process/renderer with zero growth across all ten lifetime counters. Empty container 0 retains one hierarchy entry and no Element/Yoga node. The ordinary mounted fixture has 8 elements, 9 hierarchy entries, 2 subjects, 8 Fibers, 7 public mappings and 2 registrations.
- XF-LIFE-001/002/003/006/007/010 are ordinary passing invariants. Remaining signatures are three early creates (004), same-ID reparent destruction with dangling hierarchy (005), a stale cross-parent clone child and six fake nodes (008), and one abandoned prospective Suspense leaf (009).
- The transaction record includes three-repetition regular and 100,000-row production measurements, substantial timing variation, Node's missed 120 Hz input target, and a Wasm large-table observation tail of 278.50 ms versus Stage 1's 217 ms. These are measurements, not isolated causes or universal CI thresholds.
- Hosted evidence in the record is historical: the inspected Stage 1 run passed JavaScript, Windows native and Linux native/Node gates, but its real Wasm fixture lost the WebGPU device and the browser smoke did not run. Inspect current hosted status afresh; committed configuration and local success do not prove hosted coverage.

Deliverables:

1. Stage prospective host trees without publishing side effects.
   - Replace the single mutable cloningNode context with surface-owned committed state and independently composable prospective descriptions. Immutable host descriptions traversed from newChildSet are acceptable; a global append-only log of every render attempt is not.
   - Make createNode, all clone variants, appendChild, createChildSet and appendChildToSet operate on prospective descriptions only. They must not create/patch native elements, mutate live Yoga/hierarchy, allocate widget resources/subjects, publish public-ID bindings, or replace committed event/Fiber ownership before completeRoot.
   - Preserve generated numeric identity across clones of the same host lifetime, while keeping prospective props and child lists separate from committed descriptions. Preserve prop removal and guarded-null behavior, root metadata, nested children and sibling order.
   - Scope publication state explicitly by Fabric container/surface. Continue supporting only surface 0; reject unsupported surfaces instead of silently aliasing them. Do not add multiple native windows.
   - Isolate interleaved clone branches, rapid updates, interrupted renders, Suspense fallback/reveal and abandoned work. A discarded candidate must not alter the committed tree or steal a live public ID, handle, registration lease or event target.
   - Give prospective records and committed snapshots bounded ownership. Avoid permanent maps retaining every allocated description or Fiber. Release or replace bridge-owned candidate references safely on publication, abandonment and disposal, without depending on an abandoned-render callback that Fabric does not provide.

2. Publish exactly once at completeRoot and preserve committed JavaScript ownership.
   - Derive the final candidate from the actual newChildSet and compare it with the last successfully published description. Publish only reachable prospective nodes; do not flush abandoned operations merely because they were observed during render.
   - Submit one structural native call per completeRoot publication, including accepted empty/unmount/no-op publications under an explicit policy. React renders that bail out without completeRoot are not publications. Do not add hidden per-operation structural calls before or after the batch.
   - Route ordinary Node render and the ordinary Wasm ReactNativeWrapper through this collector. Direct-batch fixtures alone do not establish migration of the application path.
   - Publish committed Fiber/native-target/public-ID mappings at the acknowledged publication boundary, before commit callbacks and effects that require live targets. Keep previously committed mappings usable while prospective work is pending.
   - Consume actual destroyed IDs through existing idempotent lifetime cleanup. Preserve surviving registrations, captured native lifetimes, Strict Mode leases and public-ID rebinding; avoid clearing and rebuilding all registries at each commit.
   - Preserve events and imperative widget calls against the committed tree while a candidate is pending. New mounted handles must work after publication; removed handles/events must be rejected after acknowledgment. Retain Wasm's deferred event drain and avoid callbacks under native tree locks.
   - A rejected or failed publication must not install its candidate as successfully committed JS state or run a success completion path. Define and test recovery or explicit failure without leaving usable JS mappings pointing at unacknowledged native state.

3. Replace the alpha structural bridge with one explicit publication protocol.
   - Retain shared native parser/application infrastructure, binding parity, the surface policy, native ordering authority and lossless counters from Stage 2.
   - Define a new schema version for final-tree publication through the shared ApplyCommit path. Remove schema-v1 application support and explicitly reject v1 payloads before mutation; do not reinterpret their shape under new semantics. Versioning identifies the accepted contract and detects stale callers, rather than requiring simultaneous support for old versions.
   - Remove the old immediate setElement, patchElement, setChildren and appendChild binding exports and their compatibility dispatch/application paths. Replace or privatize corresponding native structural entry points so supported callers cannot bypass atomic publication. Keep Fabric host methods with those names where required by the renderer, operating only on prospective descriptions. Migrate repository structural callers, binding declarations, examples and test helpers to the new publication path; account explicitly for any experimental binding outside the supported Node/Wasm scope instead of retaining a second mutation engine for it.
   - Specify the exact envelope, complete-root/ownership information, operation semantics, result/error fields, numeric ranges, unknown-field policy and native revision behavior. Keep public string IDs in the JS binding domain.
   - Validate the entire candidate and all synchronously consumed props before changing live state. Define duplicate creates, repeated child assignments, missing/forward references, measured Yoga leaves, root restrictions, final duplicate ownership and cycles.
   - Permit a valid same-ID move within one publication despite temporary detach or attachment order in its description. Validate final relationships instead of rejecting a valid move because of intermediate ownership.
   - Continue rejecting ambiguous destruction/recreation of the same ID in one publication unless an explicit generation mechanism makes acknowledgment ownership safe. Do not introduce generation-based identity merely to avoid this restriction.
   - Define surface ownership and any supported direct publication callers using the same new protocol. Publication cleanup must not silently sweep unrelated unowned objects, and a competing publication must not cause a stale JS description to overwrite native changes unnoticed. Reject ownership conflicts or unsupported writer mixing before mutation; do not implement mixed v1/new-protocol support.
   - Preserve non-mutating preflight rejection and synchronous publication completion. All accepted publications share the same native sequence/revision authority; diagnostics resets must not reset it. Caller correlation is not ordering. Old structural argument/return shapes, stale compatibility no-ops and ordered immediate destruction are not requirements of the new API.
   - Keep existing initialization/ready callbacks and imperative widget APIs. Do not move all widget commands or asynchronous resource completion into a new total-order protocol.

4. Publish native state atomically and destroy from final reachability.
   - Serialize preflight and application against other structural writers. Establish one visibility boundary covering creates/patches, hierarchy and Yoga publication, reachability-based deletion and revision advancement.
   - Audit render access, synchronous native getters and diagnostics construction so a reader cannot observe an intermediate successful publication. A dispatch mutex alone is insufficient if renderers/readers do not participate in it.
   - Respect the established lock order. Separate lock-owning public dispatch from private mutation helpers as needed; do not recursively acquire tree locks or invoke user/JS callbacks while holding them.
   - Use synchronous binding completion with a transaction-wide lock or staged publication. An accepted call must finish native application and cleanup before returning its acknowledgment; Fabric must install committed JS ownership before success callbacks and effects. Do not substitute fire-and-forget delivery or add an adapter to preserve removed APIs.
   - Compute deletion from the final reachable set of the managed committed surface, not each intermediate setChildren removal. Detach/reassign Yoga ownership without destroying survivors; publish ordered parent/child relationships consistent with native hierarchy and Yoga.
   - Preserve the exact native Element, internal subject, registration lifetime and populated PlotBar/Table data for a same-native-ID move. Delete each finally unreachable element once, preserve resource destructors, and return only IDs actually destroyed, with a documented deterministic order.
   - Cover partial virtual-root removal, moving a surviving descendant out of a removed ancestor, deep deletion, keyed replacement and direct populated-root unmount. Empty container 0 retains its fixed metadata entry without acquiring an Element/Yoga node.
   - Advance successful native revision once per accepted publication and expose the completed result after all tree locks are released. Request rendering once through the existing publication-level wake/notification mechanism, with no per-operation wakeups; preserve the current backend render cadence.
   - Keep full preflight rejection non-mutating. Define an honest unexpected-runtime-failure policy: restore a coherent committed state, or explicitly fail/quarantine the surface so partial state cannot continue as a healthy published tree. Full rollback of arbitrary resource/allocation failures is not required, but releasing a partially updated tree for normal drawing under the old successful revision is not an atomic-publication success.
   - Retain ReactivePlusPlus/RxJS and bounded request/result/subscription ownership. Do not retain completed trees, large batches or destroyed Fiber graphs in replay subjects.

5. Turn the Stage 3 defects into regression gates on the actual application path.
   - Convert XF-LIFE-004 and 009 to passing invariants: speculative creation, patching, public-ID rebinding and abandoned Suspense work must never change published native or committed JS state.
   - Convert XF-LIFE-008 to a passing ordinary React cross-parent remount case: React may allocate a new native ID, and the old host lifetime must be destroyed and unmapped correctly. Do not claim React keys preserve identity across different parents.
   - Convert XF-LIFE-005 to a passing same-native-ID move within one final-tree publication, asserting retained widget data, ownership and subjects. Separately verify that a node omitted from one accepted publication is destroyed and cannot be moved as the same lifetime by a later publication. Replace the earlier per-operation detach/attach characterization with these tests; do not preserve its dangling-hierarchy behavior as compatibility coverage.
   - Retain all ten defect IDs as executing coverage. Remove expected-failure handling only when the intended new invariant passes; explain fixture migrations and secondary signature changes. No broad skips, weakened assertions, hidden XPASS or relabeling a remount as state-preserving reparenting.
   - Add clone-branch isolation, prop-only and children-only updates, reorder, public-ID reuse during pending work, Suspense abandon/retry/reveal, Strict Mode, rapid publications, stale events/handles, rejected publication and recovery/failure-policy tests.
   - Add deterministic native visibility tests through real subject delivery. Coordinate a reader/render attempt with a publication held between internal operations and prove it cannot observe mixed props/hierarchy/Yoga or partial deletion; do not rely on sleeps or occasional snapshots missing the race.
   - Exercise the same valid, invalid and reparenting wire fixtures through current-source Node and Wasm. Compare results, errors, revisions, actual widget state and ownership. Migrate applicable Stage 2 parity assertions to the new protocol and add explicit rejection checks for removed wire versions; account for tests whose old operation semantics are intentionally replaced.
   - Extend the isolated development/production fake Fabric harness to model publication, final reachability and staged versus committed mappings, while keeping real native tests as the authority for locks, Yoga and resource lifetime.
   - Add bounded publication/call/revision and staging diagnostics proving one structural call and one revision per accepted completeRoot and identifying failed publications. Distinguish speculative host observations from native publication traces; do not implement a durable recorder or full frame-correlation system.

Scope and constraints:
- Preserve Fabric, React 19.2.3, RN 0.87.0, RxJS, ReactivePlusPlus, Yoga, Dear ImGui and public component/widget APIs. Modify owned host/binding/native seams rather than generated renderer snapshots.
- Implement the complete vertical path from real Fabric prospective work through completeRoot, native publication, acknowledgment, JS ownership and later-frame validation. A fake-only collector or direct-native batch demo is insufficient.
- Deriving a final candidate and omitting unreachable speculative nodes is required for correctness. Optional operation coalescing, binary transport, generic diff optimization and full widget-state serialization are outside this slice unless a measured correctness blocker requires a narrowly documented change.
- Keep one existing render notification per publication separate from Stage 4 scheduling. Do not add dirty/active scheduling, replace the fixed loop, implement general invalidation generations, or claim physical presentation/frame-revision correlation.
- Do not add durable trace/replay, automation APIs, dependency upgrades, CMake consolidation, new widgets, macOS support, multiple windows, publishing or a general asynchronous shutdown redesign.
- Preserve the authoritative npm workspace lockfile and supported toolchains. Process exit, forced GC, dropped updates, destroying surviving widgets or whole-registry resets must not substitute for correctness and cleanup.
- Map/Canvas benchmarks, hardware WebGPU baselines, ubx-monitor integration and Electron/GPUIX comparisons remain open. Stage 3 completion does not complete Stage 0 coverage or the Stages 0-4 milestone.
