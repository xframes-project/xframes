/goal

Implement the next Phase 12 vertical slice: Stage 1 explicit cross-runtime destruction and lifetime cleanup across Node/OpenGL and Wasm/WebGPU.

Primary outcome:
A React application can repeatedly mount, update, reorder, replace, remove, and unmount registered widgets without accumulating native elements, Fiber mappings, public/native ID mappings, widget registrations, or internal-operation subjects. Destroyed targets cannot receive callbacks or imperative updates, and stale handles cannot mutate a replacement widget. Prove this across at least 1,000 cycles in each real runtime using the existing harness.

This slice implements cleanup around the current native destruction path. Atomic publication, speculative-work isolation, and reparent-safe final reachability remain Stages 2-3; render scheduling remains Stage 4.

Starting evidence:
- Commit 4256d19 delivered the first Stage 0 slice: real development/production Fabric lifecycle tests, native queue tests, opt-in diagnostics, shared PlotBar/Table fixtures, production baselines, and application-code CI configuration.
- Each 1,000-cycle real-runtime stress run accumulated 2,000 native elements, 8,000 Fiber mappings, and 2,000 widget registrations after warm-up. Internal subjects returned to zero because the fixture removed its expensive subtree before root unmount.
- XF-LIFE-001/002/003/006/010 identify retained Fiber mappings, retained registrations, forwarded stale imperative calls, late event callbacks, and missing container-root destruction.
- XF-LIFE-007 shows that removing a public string ID can overwrite native numeric identity with null during cloning. Fix this identity boundary as part of reliable lifetime bookkeeping.
- XF-LIFE-004/005/008/009 cover pre-completeRoot publication, same-native-ID reparent destruction, incomplete cross-parent clone staging, and abandoned Suspense work. Keep these as executing characterizations for later atomic staging/reachability work.
- Local Windows/Linux native tests and real Node/Wasm fixtures passed with documented expected failures. Hosted CI was configured but had not run in the baseline session; verify its actual status separately when available.

Deliverables:

1. Make native destruction explicit, including virtual container roots.
   - Correct SetChildren(0, ...) so removing or replacing roots recursively destroys detached subtrees even though container 0 is not an Element. Cover direct populated-root unmount, multiple root children, partial removal, and repeated empty unmount.
   - Preserve cleanup of hierarchy entries, Yoga ownership, internal-op subjects, diagnostic per-element state, and widget-owned resources. Surviving siblings and ordinary reorders must retain identity and state.
   - Collect actual destroyed IDs and expose them through one shared cleanup contract in Node and Wasm. A synchronous result or ordered notification is acceptable; document its ordering and completion boundary.
   - Include all descendants, report each actual destruction once per operation, and make duplicate cleanup delivery harmless. Native ownership is authoritative; do not infer successful destruction solely from JS prop diffs or diagnostic snapshots.
   - Respect hierarchy/element locks. Do not call JavaScript while holding native tree locks or introduce blocking cross-thread callbacks. Give new notification payloads, queues, and subscriptions explicit ownership and teardown.

2. Release JavaScript mappings and registrations by native lifetime.
   - Add reverse native-ID/public-ID lookup and idempotent cleanup of Fiber entries, forward/reverse mappings, registration sets, and per-target references when native destruction is acknowledged.
   - Handle nodes with no public ID and effect registrations that occur separately from native creation. Delayed effects must not resurrect destroyed registrations; delayed cleanup must not remove a newer owner of a reused public ID.
   - Audit registration effects across existing components, including plots, Table, Map, and Canvas. Pair registration with cleanup using a shared approach where practical. Strict Mode setup/cleanup/setup must leave a still-mounted widget usable.
   - Keep numeric native identity immutable through every create/clone/patch path. Treat public string ID addition, change, removal, and reuse as mapping operations; never serialize that public ID or null over native numeric identity.
   - Define and test ownership when public IDs are rebound: old cleanup removes only the binding it owns. Avoid unbounded tombstone collections or scanning every widget for each destroyed ID.
   - Dispose cleanup/event subscriptions and retained bridge references on teardown. Cleanup must work with diagnostics disabled, without test-only polling or manual map resets.

3. Reject events and imperative operations targeting dead widgets.
   - Check liveness at React event dispatch, including already queued or replayed events. Never invoke Fabric's event handler with an undefined or destroyed Fiber target.
   - Define ordering across native destruction, cleanup acknowledgment, and JS dispatch. Test delayed notification/event delivery; document when unmount cleanup is complete rather than assuming unrelated callback queues are ordered.
   - Drop stale or unknown-target events and expose bounded diagnostic counters. Preserve normal event delivery for surviving and newly mounted widgets.
   - Make saved imperative handles harmless after deletion, including after replacement/public-ID reuse. Preserve valid operations before deletion; operations arriving after destruction must not recreate native state or internal-op subjects.
   - Use a consistent, documented stale-handle behavior compatible with the current API (prefer a no-op with a diagnostic counter). Do not suppress unrelated validation/runtime errors.

4. Turn the baseline into a passing cleanup regression gate.
   - Extend the real Fabric fake-binding suite in isolated development and production runs. Model native destruction acknowledgments, including delayed/duplicate delivery, instead of directly clearing adapter state in tests.
   - Cover deep deletion, insertion/removal/reorder, keyed replacement, direct populated-root unmount, rapid updates, Strict Mode, public ID mutation/reuse, late effects, stale callbacks/handles, and bridge disposal with queued notifications.
   - Extend native tests through actual queue/subject delivery. Assert exact destroyed-ID sets, native counts, hierarchy/Yoga consistency, subject cleanup, and retained state of surviving widgets.
   - Run the shared PlotBar/Table fixture on current-source Node and Wasm binaries. Exercise both subtree removal before unmount and direct unmount while populated widgets remain attached.
   - Run at least 1,000 lifecycle cycles in one process/renderer per runtime, alternating meaningful removal/replacement cases. After cleanup acknowledgment and an observable frame, require zero growth from the empty post-warm-up baseline in native elements, hierarchy entries, subjects, Fiber entries, forward/reverse mappings, and registration sets.
   - Keep fixed empty-container metadata explicit. Assert expected live counts and working events/imperative updates while mounted, so dropping all work cannot pass the cleanup checks.
   - Retain semantic content assertions, populated screenshots, timeouts, bounded traces, count deltas, and failure artifacts. Process exit, forced GC, RSS alone, or wholesale registry resets are not proof of unmount cleanup.

Scope and constraints:
- Preserve Fabric, React 19.2.3, RN 0.87.0, RxJS, ReactivePlusPlus, Yoga, Dear ImGui, and public widget APIs. Modify owned host/binding seams rather than generated renderer snapshots.
- Integrate cleanup into ordinary Node and Wasm wrappers, not only the harness. Keep direct native callers compatible when adding results or optional callbacks; avoid a new mandatory init argument without a compatibility path.
- Keep individual-operation publication and rendering policy unchanged. Do not implement ApplyCommit, schema/revision machinery, commit batching, speculative staging, reparent-safe reachability, or invalidation scheduling here.
- Do not sweep all currently unreachable nodes after every operation: that conflates prospective work and same-ID moves with accepted deletion before Stage 3 exists.
- Preserve existing resource destructor behavior. General asynchronous resource/renderer shutdown redesign, new widgets, macOS support, publishing, CMake consolidation, and dependency-version upgrades are outside this slice.
- Remaining Map/Canvas benchmarks, hardware WebGPU baselines, ubx-monitor integration, and Electron/GPUIX comparisons stay open. Ordinary cleanup does not complete Stage 0 or the Stages 0-4 milestone.
- Use the authoritative npm workspace lockfile, supported VS2022 toolchain, and documented Docker Wasm build. Keep raw results and generated build artifacts out of source changes.
